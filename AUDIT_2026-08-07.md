## Required remediation before Milestone 5

### 1. Protect every state-changing route

`requireLocalJsonMutation` is used by `app/api/ideas/[ideaId]/route.ts`, but the same loopback, JSON content-type, origin, and cross-site protection is missing from these state-changing routes:

- `app/api/ideas/route.ts`
- `app/api/editorial-notebook/route.ts`
- `app/api/board/[ideaId]/route.ts`
- `app/api/intake/route.ts`
- `app/api/intake/[ideaId]/route.ts`

Apply the guard consistently and add route-level tests for rejected non-JSON, non-loopback, foreign-origin, and cross-site requests.

### 2. Correct recommendation disposition hydration

`setRecommendationDisposition` persists the author's decision in `recommendation_dispositions`, but `readFinalReview` reconstructs `recommendationStatuses` from older synthesizer JSON without overlaying current dispositions. A saved selection can therefore reset after reload.

Overlay persisted dispositions when reading a final review. Add an integration and browser regression test that saves a disposition after final review, reloads the idea, and confirms that the selected disposition remains visible.

### 3. Make live-run preview read-only

Opening an idea requests `execution=live_preview`. The estimate path calls `refreshContent`, which can synchronously read and parse the BOK and write index/version records. A display-only cost preview must use the already indexed content state and must not refresh source files or perform indexing.

Keep content indexing and source refresh explicit. A live execution may validate that indexed versions are ready, but ordinary page load and estimate generation must not trigger long indexing work.

### 4. Align safe budget defaults

Documentation says the normal cap is USD 0.05 and the maximum is USD 0.25. The committed fallbacks in `src/ai/model-routing.ts` are USD 0.50 and USD 1.00. Change the committed fallbacks to match the documented finance policy and add exact-value tests.

Do not read, create, print, or commit environment values while making this correction.

### 5. Verify a current database backup

Before applying migrations 007/008 to meaningful local data, create a new owner-only SQLite backup, run `PRAGMA integrity_check`, and document a successful restore test against a copy. Never add the database or backup to Git.

### 6. Complete escalation learning

The live path records escalation reason, previous call, provider, model, usage, cost, and latency. Complete the remaining contract:

- record whether the escalated result was accepted;
- record whether it influenced the final draft;
- record whether escalation materially improved the accepted result;
- support comparison with the lower-cost output;
- expose explicit high-tier escalation in the UI without enabling automatic escalation.

### 7. Reconcile documentation and repository state

`IMPLEMENTATION_STATUS.md` contains older, contradictory provider-routing entries below the current OpenAI policy. Clearly mark those dated sections as historical and superseded. Do not treat historical validation counts as current proof.

Prepare the Git index only after remediation. The current working tree contains staged, unstaged, and untracked application files; committing the existing index would not reproduce the tested application. Continue excluding environment files, keys, SQLite files, backups, BOK content, voice-skill content, Notebook content, `archive/`, PDFs, and user images.

## Publication UX follow-up audit — 2026-08-07

### Verdict

**Remediation is still required before Milestone 6.** The normal LinkedIn-only and Medium/LinkedIn happy paths are substantially implemented, and exact-version publication integrity is generally strong. The remaining gaps concern out-of-order dual-output sequencing and inconsistent enforcement of published-workflow locks.

### Required findings

1. **Dual-output dead end:** Finalize can be opened before a companion exists, the canonical article can be published there, and Write then disables companion creation because the primary output is published.
2. **Service-layer lock gap:** the idea API route blocks Board reruns after publication, but the underlying deterministic Board, grounded/live Board, single-reviewer, development, and general update services do not consistently enforce the same policy.
3. **UI lock gap:** targeted reviewer reruns and optional polish actions remain active after publication. Retrospective recommendation dispositions and escalation assessments need an explicit product decision.
4. **Voice-check boundary:** the client blocks checks for a published exact version, but the pure local voice-check endpoint is not version aware.
5. **Execution clarity:** the free deterministic test makes no provider call, but it appears under live-run settings immediately after live-budget warnings and can therefore be misunderstood.
6. **Terminology and documentation:** some links still say `Draft` instead of `Write`, and current status claims overstate the completeness of the published-output lock.

### Confirmed strengths

- Finalize previews are read-only and publication actions send the exact draft ID, format, platform, and text.
- The service rejects mismatched platforms, stale companions, non-current drafts, and duplicate exact-version publication records.
- Canonical and LinkedIn companion drafts have independent versions, reviews, voice checks, and publication records.
- Canonical edits correctly make linked companions stale.
- Principal draft save/review/visual controls are service-blocked for published exact versions.
- User, stored, BOK, voice, and repair content is placed within escaped untrusted-context boundaries before model use.
- Live high-tier reviewer escalation remains explicit; deterministic execution does not call a provider.

### Missing regression coverage

- Out-of-order Finalize access before companion creation.
- Publishing the canonical article before companion preparation and verifying prevention or recovery.
- Direct service rejection for every post-publication workflow mutation.
- All applicable UI controls disabled after publication.
- Exact article-versus-companion text identity in both publication records.
- Deterministic-test messaging that cannot be confused with live budget validation.
- Malicious stored-note and malicious retrieved-BOK cases.

### Disposition

All findings above are **open**. The bounded remediation work and acceptance criteria are recorded in `BUILD_ROADMAP.md` under **Required publication UX audit-gap checkpoint — before Milestone 6**. Historical findings earlier in this document remain preserved as dated evidence.
